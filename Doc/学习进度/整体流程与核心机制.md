## 一、整体流程

1. **UI 接收消息**：调用 `ChatViewModel.sendMessage(content)`
2. **开始 agent 流程**：`MainEntryNew.runWithSession(userInput, sessionId, application)`
3. **agent 初始化**：`initialize`
4. **创建会话 + 构造上下文 + 系统提示词**：`SessionUiContext`、`getRecentMessages`
5. **创建新 AgentLoop**（`AgentLoop.kt`）：达到最大轮次 / Agent 认为可以结束，退出 loop
6. **退出方式（四种）**：
   - LLM 给出最终回复
   - 达到最大轮次
   - 循环检测出循环（同一操作多次）
   - 手动停止
7. **进度展示**：`SessionFloatWindow`（悬浮窗步骤）+ `uiProgressFlow`（聊天界面流式气泡）
8. **会话保存**：`sessionManager.save(session)`
9. **记忆更新**：`queueMemoryEvolutionEvent`
10. **finally 统一收尾**

## 二、runWithSession 核心流程

1. **会话隔离**：`getOrCreate(sessionId)`
2. **构建 System Prompt**：`ContextBuilder.buildSystemPrompt(userGoal)`
3. **创建独立 AgentLoop**：`createSessionScopedAgentLoop()`
4. **启动进度监听**：`progressFlow.collect → handleProgressUpdate`
5. **执行 ORA 循环**：`AgentLoop.run(systemPrompt, userMessage, history)`
6. **结果处理**：去 reasoning tag → 通知 → 远程回执
7. **落盘 + 记忆**：`extractRunDeltaMessages → save → queueMemoryEvolutionEvent`

## 三、agent-loop 核心（AgentLoop.kt）

1. **注册工具**（agent 工具 + 安卓相关工具）
2. **决定 agent 用啥工具**（关键词匹配 + 小模型判断，**优先后者，前者降级**）
   - `onDemandNames = LlmOnDemandToolInclusion.resolveInclusions(systemPrompt, userMessage)`（关键词匹配、SKILL 兜底）
   - `outcome = LlmToolRouter.runRouterLlm`（小模型判断选哪些工具）
3. `suspend run`（调用 `runKotlinLoop` —— 真正的核心）
4. **动态工具载入**（上面的第 2 步）
5. **组装 message**
6. **loop until shouldStop**：
   - `enforceContextBudget`（上下文裁剪）
   - 解析结果是否返回工具调用：
     - **返回工具调用**：检测是否循环调用同一个工具
       - 两个等级（**CRITICAL**，直接失败；普通循环，把结果发给模型提醒它）
     - 如果没有循环调用 → 执行工具调用（记录 + 执行）
     - 后处理
7. **Loop 终止**（LLM 不再调用工具 / 达到最大迭代次数 / 被取消 / 报错）

### run() 结构树

```
run(systemPrompt, userMessage, contextHistory)
  └─ runKotlinLoop()
      ├─ 工具路由：决定用哪些工具
      ├─ 组装 messages：[system, 历史对话, user]
      │
      └─ for 1..maxIterations (默认 40 轮)
          ├─ 检查 shouldStop
          ├─ 裁剪上下文（删最早的 tool 消息）
          ├─ callLlm → 发消息给 LLM
          │   └─ 流式推送思考/回答到 UI
          │
          ├─ LLM 返回了工具调用？
          │   ├─ 逐个执行工具
          │   │   ├─ 循环检测 → 发现循环则终止
          │   │   ├─ executeTool → 实际执行
          │   │   ├─ snapshot 过期？自动提示刷新
          │   │   └─ 结果追加到 messages
          │   └─ continue → 下一轮迭代（LLM 看到工具结果）
          │
          └─ LLM 返回了纯文本？
              └─ 这就是最终答案 → break

      └─ 返回 AgentResult（最终回复 + 工具列表 + Token 消耗）
```

## 四、deviceTool.kt：核心 device 工具

总共 **16 个操作**，覆盖：读屏幕、点击、滚动、截图等。

```kotlin
when (action) {
    "snapshot"   → executeSnapshot(args)      // 拍屏幕快照（读控件树）
    "screenshot" → executeScreenshot(args)     // 截屏（像素图片）
    "act"        → executeAct(args)            // 执行操作（点/滑/打字...）基于 kind 不同路由到不同具体操作
    "open"       → executeOpen(args)           // 打开 App
    "status"     → executeStatus()             // 查询设备状态
    "clipboard"  → executeClipboard()          // 读写剪贴板
}
```

**无障碍树**：`val viewNodes = proxy.dumpViewTree()` ← 调用 AccessibilityService 拿树

**核心亮点**：
- 广告过滤
- 提示按钮防误触
- ref 过期检测
- 包名一致性校验
- 自动弹窗关闭

> 广告过滤：广告控件关键词检查 + 广告内容文本匹配检查
> Ref 过期检测：每次使用无障碍树的 snapshot 时校验时间戳，**超过 20 秒就要去取新树**

## 五、记忆系统

### 架构（4 个文件，都在 workspace/memory/ 下）

| 文件 | 作用 | 上限 |
|---|---|---|
| `MEMORY.md` | **长期记忆**（入口1）：Agent 任务沉淀的操作经验/用户偏好/失败教训/项目上下文 | 16K 字符 |
| `IMAGE-MEMORY.md` | **相册记忆**（入口2）：扫描相册截图 → VLM 摘要 → 建立主题/内容索引 | — |
| `USER-PROFILE.md` | **用户画像**：由长期记忆 + 相册记忆共同构建，默认加载 | 16K 字符 |
| `yyyy-MM-dd.md` | **每日日志**：Agent 每次任务事件先归档到当日日志，再进长期记忆 | — |

### 三个入口

1. **Memory Evolution** —— Agent 任务结束后自动触发记忆入队（`MainEntryNew.runWithSession()` 结束）→ 批处理沉淀到 `MEMORY.md`
2. **相册记忆** —— 独立的。用户手动点屏幕触发，或 24h 定时任务
3. **记忆索引 + 记忆检索** —— agent 调用 `memory_search` 工具，检索每日日志

### 入口 1：长期记忆 `MEMORY.md`

**生产**：每次 Agent 流程处理完之后，调用 `queueMemoryEvolutionEvent` → `MemoryEvolutionManager.recordAgentRun`（Agent 事件写入 `pending.jsonl`，等待后面写入 memory）。

> **核心设计意图**：防止单次任务污染长期记忆 —— 如果任务失败了、异常了、或者用户只是随便试试，这些事件都不会直接写进 `MEMORY.md`。它们先躺在 pending 队列里，等定时任务或用户指定来**批量审核**后才落地。

**消费**：`MemoryEvolutionSkill.kt` → 调用 `manager.runEvolution()` → `MemoryEvolutionManager.runEvolution` 消费核心链路：

1. `allEvents = readPendingEvents()` 去 jsonl 队列拿事件
2. **归档当日日志**：`memoryManager.appendToToday(formatDailyEvent(event))` 按事件写入 `yyyy-MM-dd.md`
3. **LLM 评判有价值的记忆**（4 类）：
   - `USER_PREFERENCE` 用户偏好（记住、我喜欢、不要等词汇）
   - `TASK_WORKFLOW` 可复用工作流
   - `FAILURE_LESSON` 失败经验（报错、权限问题等）
   - `PROJECT_CONTEXT` 关键上下文信息
4. **过滤**（保留项）：
   - 关键词匹配敏感词汇过滤（密码、apiKey、token、银行卡等）`MemoryEvolutionPolicy.isSensitive`
   - 去重 `distinctBy(category + normalizeForDedupe(title+content))`
5. `mergeGlobalMemory` 合并全局记忆（模板、记忆上限 16K）

> ⚠️ **2026-08 已改造**：旧的"置信度阈值（confidence >= 0.55）+ 关键词启发式评分"已删除，改为 **`judgeMemory()` 用 LLM 直接评判**：每个事件发给模型，返回 `{valuable, category, title, content}` JSON，模型按 4 类判断是否值得沉淀。LLM 失败则跳过该事件（不阻断整轮）。全局记忆 16K 分 4 块（对应上述 4 类）合并。

### 入口 2：相册记忆 `IMAGE-MEMORY.md`

**触发方式**：`syncGalleryMemories()` 每 24h 定时触发扫描，也可以 UI 手动点击扫描。

> **相关背景**：安卓系统的底层相册索引管理用的是 SQLite，每张相册里的图片都有一个主键 id。

**流程**：触发 → 游标扫描（MMKV 存索引位置）→ 去重 → 压缩 → VLM 调用摘要 → 隐私过滤 → 写入 image-memory → 建立 user-profile。

1. **触发入口**：`syncGalleryMemories()` 定时或 agent 手动
2. **游标扫描 + 去重 + 压缩**：`AlbumScanCursorStore.kt`、`AlbumScanner.kt`、`ImageMemorySummarizer.kt`
   - MMKV 存储：存时间戳（秒级）和图片 ID，**增量扫描**，不扫全表；MMKV 没有过期时间
   - 从已有的 `IMAGE-MEMORY.md` 去重，基于文件名
   - 压缩图片 → 调 VLM，系统提示词强调输出 JSON
   - JSON 形式：`{"summary":"...","extracted_text":"..."}`
   - **降级策略**：VLM 调用失败时，直接基于元数据生成摘要（面试可能问：不输出 JSON 咋办 → 用正则提取 JSON 块 + 元数据兜底）
3. **数据脱敏**：`ImageMemoryPrivacyFilter` 正则匹配 + 身份证、银行卡、api、住址等关键字脱敏
4. **生成 image-memory.md**：`GalleryMemoryRepository.kt`

大致结构：
```markdown
# Image Memories

## IMG_20240813_123456.jpg
- time: 2024-08-13 12:34:56
- summary: 用户在餐厅拍摄的晚餐照片，桌上有一份牛排和红酒，环境温馨。
- extra_text: xxxx
```

### 画像构建 `USER-PROFILE.md`

调用链：`GalleryMemoryWorkflow.kt:194-199` → `UserProfileGenerator.kt:59-133` `buildUserProfile()`

- **4 个来源打包构建画像**：`IMAGE-MEMORY.md`、近 3 天日志文件、`MEMORY.md`、agent.md
- **画像 9 维度**：身份（名字/角色/agent.md 关键词/国家/时区）、稳定偏好、兴趣、作息（最常活动时段）、上下文提示、隐私等级、近期细节等

整体格式架构：
```markdown
# USER-PROFILE
## Stable      ← 稳定画像（默认加载）
## Recent      ← 近期摘要（默认加载）
## Sources     ← 数据溯源（默认加载）
```

### 入口 3：记忆索引 + 记忆检索

调用：`memory_search` 工具（`MemorySearchSkill.kt`）

> **相关背景**：安卓自带 SQLite，高版本自动支持 FTS5（BM25 全文检索）。**只索引 `IMAGE-MEMORY.md` 和日志文件 `yyyy-MM-dd.md`**。

- **索引构建**：每日日志在 `appendToToday()` 触发构建；`memoryIndex?.indexFile(logFile)`
- **检索**：BM25 关键词 + 向量检索（hybrid search，`MemoryIndex.kt`）

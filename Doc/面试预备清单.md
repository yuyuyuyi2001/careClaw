## 0. 项目一句话定位（开场用）

> CareClaw 是一个**纯 Kotlin、跑在安卓手机上的多模态 AI Agent**（Observe–Reason–Act），目标是"帮不太会用手机的父母远程装软件"：子女远程/父母语音一句话，Agent 自己看屏幕、自己想步骤、自己点屏幕装好，并把使用习惯沉淀成长期记忆。核心差异化：**端侧执行、隐私可控、跨应用可教（SKILL）**。

## 各亮点面试口头描述（背诵版）

**亮点1（感知与接管）**
> 我做了三层混合感知：无障碍树拿控件结构和坐标，MediaProjection 截图看真实画面，息屏时自动降级到无障碍服务自带的截图 API；语音直接录音给多模态模型理解，不依赖国产机不兼容的 Google 语音。拿到界面后，Agent 走'快照→LLM 决策→通过无障碍服务注入点击滑动→再截图验证'的闭环。执行层有广告误触拦截、ref 坐标过期校验，远程指令还有白名单和高危二次确认。

**亮点2（执行框架与 ORA 闭环）**
> 端侧 Android 多模态 Agent 执行框架：指令进入后组装 system prompt，进入上限 40 次的 Agent 循环——每轮以设备 UI 快照驱动 LLM 决策工具调用，顺序执行并回填结果，配合循环检测与 75% 上下文预算，形成 Observe–Reason–Act 闭环。每会话独立循环实例、JSONL 只落增量，支持多轮工具协同与多会话并发。

**亮点3（双工具注册表）**
> 我把智能体能力抽象成统一的 Tool 接口，按跨平台通用和 Android 平台分成两个注册表，用一个分发器统一路由 LLM 的工具调用。高 token 的工具默认不进 prompt，靠首跳 LLM 路由器加关键词启发式按需装配。执行层有广告和提示按钮误触防护，外加四类循环检测兜底，被拦就回填警告让模型改思路，CRITICAL 直接熔断；远程指令还有白名单和高危二次确认。

**亮点4（多层记忆）**
> CareClaw 用三层记忆解决端侧 Agent 的持久化与上下文预算问题。工作记忆层把 MEMORY.md 等分块存入 SQLite，做 FTS5 关键词 + 向量余弦相似度的混合检索，命中片段按行号回填上下文；相册记忆层用增量游标扫描相册、VLM 生成图片摘要、正则脱敏隐私后落盘主题检索；画像进化层在任务结束时把事件写入 pending 队列，由定时任务批量聚合出可解释的 USER-PROFILE 画像，随系统提示按预算注入。

**亮点5（SKILL 固化与热加载）**
> 操作固化就是'教一次、以后照做'：用户先打开目标页面，Agent 通过无障碍服务拿到前台包名，再用 dumpsys 非 root 抓出 deeplink Intent，生成一个带 frontmatter 的 SKILL.md 放到手机磁盘。Skill 目录靠 mtime 指纹自动热加载，不用重启 App。执行时系统提示只注入技能目录，LLM 命中后用 read_file 读 SKILL.md、按步骤调 device 工具完成跳转。这样把一次成功的操作路径沉淀下来，一句话即可复用。

## 面试诚实提示（简历措辞 vs 架构现状，共 6 条）

面试前先对齐，被追问时**主动澄清反而加分**：

1. **"向量相似度匹配"是真的，但"端侧"要区分**：检索在端侧（SQLite 存向量 + Kotlin 手写余弦相似度），但 **embedding 生成走远程 API**（OpenAI 兼容 `/embeddings`，默认 text-embedding-3-small）；图片摘要也走远程 VLM。无 key/无网时降级纯关键词检索。
2. **上下文溢出恢复层是"接线预留"而非热路径**：当前真正生效的预算控制是 `AgentLoop.enforceContextBudget`（预支裁剪）；`ContextManager.handleContextOverflow` / `MessageCompactor` 已接线但不在主循环每次都触发。如实表述为"预支裁剪为主、溢出恢复机制已接线预留"。
3. **会话落盘实现**：以 `agent/session/SessionManager.kt` 为准（JSONL + 原子写 + 坏行修复 + 30 天清理）；早期文档里写的 `JsonlSessionStorage` 不存在。
4. **多会话并发**：框架层完整支持（activeSessionLoops 三张 ConcurrentHashMap + runToken），但 UI 侧通常一次一个任务——讲"多会话状态管理"时说框架已支持、日常单任务执行。
5. **热加载机制**：是 mtime 指纹懒失效，不是 FileObserver；"下次会话立即生效"，不是"运行中毫秒级热更新"——措辞别夸大。
6. **后台运行**：是"前台服务 + 无障碍系统级常驻 + 截图前台服务"的多路保活，但**国内 ROM 后台存活有上限**，演示主线靠完整权限链 + 悬浮窗进度，这个工程现实要点出来。

## 项目背景速记（帮回答"为什么做这个"）

- 定位：帮父母远程装软件的端侧多模态 Android 智能体，Observe–Reason–Act，长期记忆为核心能力。
- 形态：纯 Kotlin、单模块 `:app`、约 12K 行、无 Chaquopy/Python；改造自 X-OmniClaw。
- 核心闭环：远程/语音指令 → 感知（无障碍树+截图）→ LLM 推理 → 原子操作（搜索/下载/安装/验证）→ 回报 → 记忆沉淀。
- 差异化：智能体自主完成（父母零操作）；跨品牌跨商店可"教"（SKILL）；端侧执行、隐私可控。
- 远程入口：飞书 Bot 为主 + HTTP（NanoHTTPD 8765，`/api/inject` + Bearer）备用。
